# Catalog and Builder

**One line:** GAM's whole command catalog to browse and search, and every command that only reads run from here: GamGUI's
generic read builder, ported and held to it command by command. Slice 1 of plan §12 phase 4.

**Owns invariant 3** (only confidently read-only commands become runnable). Touches 1 (each value one argv element), 9 (the
runner's output cap; the result kept whole, bounded by it) and 11 (parity is a test).

## Files
- `Packages/GamKit/Sources/GamEngine/CommandCatalog.swift`: the vendored catalog (`Vendor/gam7/command_catalog.json`, GamGUI's
  shallow parse of the grammar, regenerated by `scripts/build_command_catalog.py` on a GAM bump) loaded into commands only it
  makes; the promotion rule; GamGUI's `parse_read_template` (slots and argv template); areas and search.
- `GamCommands.catalogRead` (in `GamCommands.swift`): the one door from a catalog command to a `GamRead`. It refuses a command
  that isn't runnable and a required value left empty; each value is trimmed and is exactly one argv element; the keywords
  around it come only from the grammar line.
- `Packages/GamKit/Sources/GamEngine/CatalogResult.swift`: a read's output as the screen shows it (GamGUI's `_render_read`,
  `cell`, `_columns_and_texts`, the CSV export).
- `UserAccess.catalogRead` (Directory): the read run on the tenant it was started on, as long as a log read may take (10 min),
  parsed off the main actor; GAM's words when it fails; a read cut off at the output cap is refused, never shown as whole.
- `App/BuilderView.swift`: the screen. `scripts/embed_gam.sh` copies the catalog into the app beside `gam7/` (never into the
  signed GAM folder).
- Tests: `GamEngineTests/CommandCatalogTests.swift`, `CatalogResultTests.swift`, `DirectoryStoreTests/BuilderReadTests.swift`,
  `WriteRouteTests.theBuilderReachesNoWrite`, `CommandKindTests.everyBuilderInTheSourceIsChecked`.
- Parity fixture: `Tests/Fixtures/catalog_reads.json`, made by `scripts/gen_catalog_reads.py`: frozen GamGUI's own read builder
  and gate run over this repo's catalog, so the same code on the same input. `bump_gam.py` runs it after `gen_fixtures.py`.

## How it works
- **Runnable** = the catalog calls it read-only (`risk` 0) and certain, GamGUI's verb rule checked again here agrees (the first
  of its first six words after `gam` holding a known verb holds a read verb and no destructive one; the verb sets are held to
  GamGUI's by the fixture), the same rule holds for the keywords the argv actually emits (`readOnly(literals:)`: the template
  keeps a word's first alternative and passes over fragments, so an edited `gam update|print user …` emitted `update`; review
  2026-10-28), and it isn't **sensitive**, judged by the verb taken from the grammar line (`verb(of:)`), never the file's. 514 of 1,051 are promoted, as in GamGUI; 13 of
  those are sensitive (GamGUI's `_is_sensitive`: every `get`, which saves a file, and `show`/`print backupcodes` and
  `browsertokens`), so 501 run.
- **Sensitive reads are browse-only here** (a deliberate difference): GamGUI runs them and audits each run as
  `sensitive_read`, never the output. This app's audit log is the executor's, for writes; a read audit is its own slice.
- **A value is never `todrive` or `doit`** (`keywordsNeverAValue`, case and underscores aside, as GAM reads a keyword): a
  deliberate difference from GamGUI, which passes them along. Some reads put a required value where GAM reads options
  (`print events [<EventEntity>] <EventDisplayProperty>*`, `print contacts <ContactSelection>`), and `todrive` there uploads the
  result as a Sheet to the admin's Drive: a write with no preview or audit (review 2026-10-28). GamGUI's Builder has the same
  hole; it's frozen, so it's noted here, not fixed there.
- **Optional `[...]` groups are dropped** (GamGUI's rule): a command runs on its required arguments, plus a person or a device on
  its own (`user <x>` when given) and a single optional placeholder. A fragment of an alternation or a paren group is passed
  over. GamGUI's quirk is kept: the sensitive rule looks for the catalog's `verb`, its first alternative, so an alternation
  line can't match it.
- **The screen**: the list by category and subcategory, runnable first, Runnable Only on by default, an area picker; a command
  shows its area, its grammar line, why it doesn't run when it doesn't, its fields, and the exact `gam` command as it's typed.
  Run (⌘R) runs that, on the domain connected at the press; one that comes back after a switch is dropped and said. The result
  is a table (`TableColumnForEach`, every column any row has) when GAM printed one, with a filter over every row (GamGUI's
  plan U1) and Export CSV… (`AuditExport`: private file, whole or nothing, formula-safe cells; a structured value as JSON), or
  GAM's words as printed.
- **Reaches no write** (`WriteRouteTests`): only `BuilderView` calls `catalogRead`, and it names no changes model, executor,
  confirmation or `AppServices`.

## Gotchas / mock-lies traps
- **The mock answers only `gam version`** of the 501. The strict mock models the exact forms this app's typed builders send
  (`formatjson` and named fields) and refuses anything else as GAM refuses what it doesn't know (`not_modelled`), never in a
  guessed shape. A generic read like bare `print users` prints GAM's flattened CSV, which the mock doesn't model: run against
  it, the Builder shows GAM's refusal. Don't widen the mock to make a screenshot run; model a shape only from GAM's source.
- **GamGUI's own caveat stands**: a grammar-valid line can still be refused live (some `print`/`show` reject what the
  grammar allows). Only the live check (B1 in docs/live-verification.md) proves a read.
- GamGUI's label code keeps the rest of a placeholder as written ("Email Address"), whatever its comment says; the fixture is
  the code's.
- **The bundled catalog isn't re-sealed at launch**: another process running as the operator could edit it. What an edit can
  do is bounded by the rules above (only argvs whose own keywords read), so it's accepted, not defended further.
- A value is trimmed as Python's `strip()` trims (`PythonText.strip`), the separator characters U+001C to U+001F too.
