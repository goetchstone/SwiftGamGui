# Catalog and Builder

**One line:** GAM's whole command catalog to browse and search, every command that only reads run from here (GamGUI's
generic read builder, ported and held to it command by command; slice 1 of plan §12 phase 4), and GamGUI's curated commands
with typed fields, their changes previewed and confirmed through ChangeCore one at a time (slice 2).

**Owns invariant 3** (only confidently read-only commands become runnable). Touches 1 (each value one argv element), 2 (a
curated change only through `BuilderChanges` and the executor), 9 (the runner's output cap; the result kept whole, bounded by
it) and 11 (parity is a test).

## How it works
- **Runnable** = the catalog calls it read-only (`risk` 0) and certain, GamGUI's verb rule checked again here agrees (the first
  of its first six words after `gam` holding a known verb holds a read verb and no destructive one; the verb sets are held to
  GamGUI's by the fixture), the same rule holds for the keywords the argv actually emits (`readOnly(literals:)`: the template
  keeps a word's first alternative and passes over fragments, so an edited `gam update|print user …` emitted `update`; review
  2026-10-28), and it isn't **sensitive**, judged by the verb taken from the grammar line (`verb(of:)`), never the file's. 515 of 1,052 are promoted (GAM 7.52.01), as in GamGUI; 14 of
  those are sensitive (GamGUI's `_is_sensitive`: every `get`, which saves a file, and `show`/`print backupcodes` and
  `browsertokens`; and here `info browsertoken` too, one enrollment token, new in GAM 7.49.00 and not named by GamGUI's
  frozen list: `CommandCatalogTests.sensitiveHereOnly`), so 501 run.
- **Sensitive reads are browse-only here** (a deliberate difference): GamGUI runs them and records each run as
  `sensitive_read`, never the output. Every other read is recorded here too now (plan F1), so they wait only on the operator's
  choice: browse-only until asked.
- **Every read run here is recorded** (plan F1, GamGUI #170), once it ends, ok or failed, in the audit log the
  executor writes: `read`, whom it was about (`target`: a catalog command's first person or group given, `Command.target`, as
  GamGUI's `_assemble`; a curated read's `CuratedCommand.target`; else "(command)"), the masked argv, `ok`, and in `extra` the
  catalog id (`command`), `origin` (`builder`; GamGUI's other, `sequence`, records a read run in a sequence, and this app's sequences hold changes only), the domain, and `rows` when GAM
  printed a table (`CatalogResult.tableRows`, GamGUI's `table_records`: a header alone is 0; words or nothing have none) or
  `error` (GAM's words). Never the output. A read the log can't record isn't shown, as GamGUI's isn't. Audit shows them (runbook
  audit-reports.md). **A read the app quits during leaves no record**: the app stops GAM and exits before the read resumes to
  write one, and reads get no begin record (they change nothing). A cancelled read task is recorded as interrupted ("Stopped
  before GAM finished, so nothing was read."), but the Builder has no Stop yet, so nothing cancels one today.
- **The read record is no write path** (invariant 2, `WriteRouteTests.theReadRecordIsNoWritePath`): `ReadAudit` holds an audit
  log and nothing else (no runner, ticket or executor), writes one action, `read`, and only `UserAccess.catalogRead` calls it;
  the app makes one in its wiring (the executor's own `AuditLog`) and hands it only to the Builder. Reads the app makes for itself
  (the directory and group caches, a person's tabs, Reports, a preview's checks) aren't recorded, as in GamGUI.
- **A value is never `todrive` or `doit`** (`CommandCatalog.keywordsThatChange`, case and underscores aside, as GAM reads a keyword): a
  deliberate difference from GamGUI, which refused only a value's raw spelling until #174 (now `as_keyword`, as here) and still
  passes `doit` along. Not `deleteduplicates` (GAM 7.49.03): despite its name and GAM's
  note, `doPrintCIDevices` only leaves a repeated device out of the output, warns, and exits 68; nothing is deleted. Some reads put a required value where GAM reads options
  (`print events [<EventEntity>] <EventDisplayProperty>*`, `print contacts <ContactSelection>`), and `todrive` there uploads the
  result as a Sheet to the admin's Drive: a write with no preview or audit (review 2026-10-28). A second line since plan F4:
  the Builder's read door (`UserAccess.catalogRead`) refuses any read GAM would read as carrying `todrive` in any element
  (`GamCommands.carriesToDrive`: stripped, lowercased, `_` dropped, GamGUI's `carries_todrive`) before GAM runs, unrecorded
  (it ran nothing), and so do the audit runs (`AuditRuns.isAuditRead`) and the export itself. A curated search whose value is
  `todrive` is refused too, though GAM reads it as a query: the stricter side, as GamGUI's.
- **Export to a Google Sheet… is a curated write, run only from its preview** (plan F4, GamGUI #174). Beside a table's Export
  CSV…, shown for a read GAM's `todrive` takes (`SheetExport.takesToDrive`: a catalog line naming `todrive`, or a curated `print`
  or `report` read; this catalog holds each command's first grammar line only, so a command whose `todrive` is on a later line
  isn't offered: the narrower side), ⇧⌘E said under it. It previews (`SheetExports.preview`): the read the table came from
  (`ReadRun.read`, the exact `GamRead`) through `GamCommands.exportToSheet` (refuses a read GAM doesn't take `todrive` on at its
  end, `GamCommands.takesToDrive`: a `print`/`report` read, or an entity's bare `list`, which `_doList` reads `todrive` right
  after, never the top-level `gam list <EntityList>`, which takes it only before its list, and the button isn't offered there
  either; review of #199, a listed deviation: GamGUI offers every line naming `todrive`), or one that carries `todrive`) is the
  read's argv then `todrive tdtitle "<domain> - <command name>" tdnobrowser true tdnoemail true`
  (`todriveArgs`, GamGUI's `todrive_args`, held to `argv.json`): no `tduser`, `tdshare`, `tdalert` or `tdnotify`. First the
  scope check, a read (`UserAccess.sheetExportScopes`: `check serviceaccount scopes <drive>,<spreadsheets>` as the connected
  admin; exit 0 or 10 is an answer, anything else or a row missing is unknown, `SheetExport.checked`). A scope known refused
  holds nothing and offers no Export, with Setup's delegation link (`SetupModel.delegationLink`: every scope this app asks for,
  never GAM's few). Unknown is said, and Export still offered. Otherwise the executor holds one `WriteStep` (`.exportToSheet`,
  target the admin, `about.command` the catalog id, the domain-wide hour (`GamRunner.domainWideTimeout`, GamGUI's
  `DOMAIN_WIDE_TIMEOUT`: the read runs again, and a cut-off leaves a file nobody can name), a click to confirm) for the tenant
  the table
  was read on (`expecting:`). The sheet shows the exact `gam …` line, a new Sheet in the admin's own Drive shared with nobody
  with no browser and no email, that it holds a **fresh read** (its rows can differ from the N on screen, every row whatever
  the filter), and each scope as Allowed, Not allowed or Not checked (words and a symbol, never color alone). Return exports,
  Escape cancels, said on the sheet. `SheetExports.confirm` runs that preview, once (`executor.run(preview, …)`, the only run;
  a second confirm is refused as spent). A switch drops a held export (`setup.onTenantChange`, and the executor's own tenant
  check), including one landing while the executor holds it: the tenant is checked again once the hold returns, and a
  mismatch discards it and says so (review of F4); Cancel discards it from the executor. The admin is named as GAM names it:
  `setup.connectedAdminPrimary` (the primary address Check access read), else the token's address.
- **The export's outcome is read from the upload's own lines** (GamGUI's failure log 2026-11-21), never GAM's one-line error
  summary: the executor keeps what a write's own output says (`GamWrite.noted`, only an export notes anything) on the end
  record and in `RunOutcome.noted`, and which steps GAM was launched for (`RunOutcome.began`: after the Vault read and the
  spawn, never on the begin record alone; a step GAM never launched has `started: false` on its end record, and its export says
  "Nothing was made: GAM didn't run", on its result and on Files). A switch landing while an export runs leaves its result off
  the screen (F6's `isConnected(to:)`, as every changes store); the jobs tray, Audit and Files keep it. `SheetExport.noted`: the link
  (`Data uploaded to Drive File:` then the link on the next line, shown as a link only when it's https on docs.google.com or
  drive.google.com with no port, user info or control character), else which failure line GAM printed about the admin
  (`uploadState`, the last line). "Nothing was made" only where GAM's source shows no file exists at that point (review of F4,
  2026-11-21, each a listed deviation from GamGUI's `UPLOAD_LINES`, which have the same gaps): `drive_refused` (the upload's
  Drive token, before the create) and `not_permitted` (`files.create` refused, a line only the upload prints) made nothing;
  `sheets_refused` and `finish_failed` made the file; `drive_off` and `not_created` (`userDriveServiceNotEnabledWarning`, which
  `files.create` and the Sheets calls after it both reach), `create_failed` (a full Drive reads the same as Google's 500
  UNKNOWN) and `probably_made` are unknown. `create_failed` is GAM's own line only, `Drive Folder: root, Create Failed:` at a
  line's start (no `tdparent` is sent), so a read's `Drive Folder: <id>, Print Failed:` (print diskusage, print emptydrivefolders)
  can't decide it. GAM names the admin by its Directory primary address (`GetTodriveParameters` → `checkUserExists`); when the
  last line names any other account it's unknown, never an earlier line (GamGUI skips it). Residue: a read acting through the
  admin's own Drive can print the upload's Drive-refused line itself, and it stands for the upload only if the upload then
  stopped with no line at all. `SheetExport.outcome` says made, not made or can't be told, GamGUI's words where the rules agree;
  exit 0 without a link is a failure (`GamWrite.notDone`, "whether a Sheet was made can't be told"); a run GAM never started
  (`began` empty) made nothing and left no record, and the result says so rather than "kept in the audit log". The result shows
  the link with ⌘O, what to do, GAM's error shown (not behind a disclosure) for a run GAM made, and whether the audit log kept
  it. A result too large for a Sheet is a plain CSV file (a drive.google.com link), said as such. The one public door a read
  takes to GAM (`AuthenticatedRunner.run(GamRead)`) refuses a read carrying `todrive` before the Vault, whichever builder made
  it (`CommandKindTests.noReadCarriesTodrive` holds every read builder too).
- **Files** (plan F4, GamGUI's `/files`, a sidebar screen): read only, no `gam`. The Sheets exported, read back from this
  app's own audit log (`MadeFiles.sheets`: each `export_to_sheet` end record with an `ok` of its own; begins, other actions and
  Mark as Checked's acknowledgement passed over; the newest 50 within the newest 50,000 records). The log and every rolled
  generation are read through descriptors opened `O_NOFOLLOW | O_NONBLOCK` and read only when `fstat` says regular file
  (`AuditLog.forEachRecord`, which Audit and Home read through too): a link, a FIFO or a folder in any generation's place is
  said, never followed or waited on. Each Sheet's time is shown in this Mac's time zone, named, and its row says what its
  result said (a Sheet made while the read reported a problem, a plain CSV file, unknown). Each kept incident's evidence folder
  with its saved reads counted by descriptor (`IncidentStore.savedReads`: the incident's folder and its `evidence` opened
  `O_NOFOLLOW`, folders only, at most `countCap` entries read; at most the store's 200 incidents). The CSVs saved through a save
  panel (`SavedFilesStore`, the newest 50, `0600` in the app's folder): every screen with one lists it
  (`WriteRouteTests.everyCSVSavePanelListsWhatItSaved`: the Builder's table, Audit, an audit run's table, an incident report's
  list, a leaver's classes, Phishing's lists, an incident log, Who it reached, Everyone it got to, a roster's issues); an
  incident report's folder and a roster hand-over ZIP aren't listed, said on the screen. A list that didn't open is said, never
  "None saved yet", and ⌘R tries it again. Return opens a Sheet or shows a folder or file in Finder; one moved or deleted since
  is said and spoken. It never lists a run folder or the setup folder (`WriteRouteTests.filesRunsNoGamAndListsNoPrivateFolder`).
- **Optional `[...]` groups are dropped** (GamGUI's rule): a command runs on its required arguments, plus a person or a device on
  its own (`user <x>` when given) and a single optional placeholder. A fragment of an alternation or a paren group is passed
  over. GamGUI's quirk is kept: the sensitive rule looks for the catalog's `verb`, its first alternative, so an alternation
  line can't match it.
- **Every command says what it does** (plan F5a, GamGUI's `gloss()`): one sentence made from the grammar line alone, so it
  says nothing the line doesn't and at worst is terse. The verb's action (`print` "List", `info` "Show details for"; any other
  verb is itself, capitalized), the keyword right after the verb in GamGUI's noun words (`cros` "ChromeOS devices"; a
  placeholder names no noun), and "for a user" or "for a ChromeOS device" from the word after `gam`. GamGUI's three noun
  tables are one here (`glossNouns`), merged as its lookup reads them, and held whole. All 1,052 commands have one, as in
  GamGUI, whose parser writes no descriptions (the generator refuses a catalog that has some, until GamGUI's
  vendored-description-wins rule is ported).
- **Search finds a command by what it does** (plan F5a; a deliberate difference from GamGUI, whose search reads only the name
  and grammar line): `CommandCatalog.Search` finds what GamGUI's finds (the text as typed, in the name or the grammar line)
  and a command whose gloss holds every word typed, each anywhere in it: "backup codes" finds `print backupcodes`, "chrome
  devices" finds `print cros`, "vault holds" finds `print vaultholds`; none did before. Words are matched in the gloss only,
  never across the grammar line, so a grammar search stays as narrow as GamGUI's ("info user" finds GamGUI's 4, where words
  across every field found 46). A curated command's description is read as its gloss. No model: plan F5b adds one.
- **The screen**: the list by category and subcategory, each row its name and, in words, what it does here and its gloss
  (GamGUI's row: "Reads · List users."; VoiceOver reads the row as one, without the dot), runnable first, Runnable Only on by
  default, an area picker, a search of names, grammar and glosses; a command shows its gloss, its area, its grammar line, why
  it doesn't run when it doesn't, its fields, and the exact `gam` command as it's typed.
  Run (⌘R) runs that, on the domain connected at the press; one that comes back after a switch is dropped and said. The result
  is a table (`TableColumnForEach`, every column any row has) when GAM printed one, with a filter over every row (GamGUI's
  plan U1) and Export CSV… (`AuditExport`: private file, whole or nothing, formula-safe cells; a structured value as JSON), or
  GAM's words as printed.
- **GamGUI's curated commands** are listed with the catalog's, in their sections, runnable first (GamGUI's `_curated() +
  shallow`): typed fields (a person or a group with the directory's or the tenant's matches as completions, a choice as a
  picker, GamGUI's words to insert under a query), the exact command as typed, and Run (a read, run as above) or Preview… (a
  change). A change is held by the executor and shown on its sheet: the summary, the command as GAM gets it (masked as the
  audit keeps it), a warning, how much it can hurt; Run is always a click (GamGUI's `confirm_step=True`), and a destructive
  one is never the default button.
- **Sequences** (roadmap 2.5, 2026-11-27; GamGUI's `/builder/sequence/*`): Add to Sequence on a change's page builds and checks
  it as Preview… does and appends it (at most `maxSequenceSteps`, GamGUI's 25); the toolbar's Sequence (N) lists them, up, down,
  remove, Clear. Preview holds them all as one change (`BuilderChanges.previewSequence`): a confirm always; the guard counts
  steps as GamGUI's does, so ten with a destructive one need `confirm` typed. A step added, moved or removed drops the preview.
  The run is the executor's, in order, each step once, a failure not stopping the rest; Stop ends it after the step in flight.
  Each step's outcome is listed after. **Deviations:** reads aren't added (GamGUI runs a read step and keeps only whether it
  ran; here a read runs from its own page and shows its table), and a failure every later step would share (sign-in expired,
  a scope missing) stops the run, as every other many-step run here does. Held to `BuilderChangesTests`.
- **Risk is GamGUI's, never below ChangeCore's floor** (`WriteAction.minimumRisk`): a random password reset and an alias removed
  are destructive here, as on every other screen. Transfer and suspend are destructive in GamGUI too.
- **Neither app's Builder sets a signature or deletes an account** (GamGUI dropped both, #149 and #166): a signature is set on
  Signatures, which keeps the one it replaces to put back; an account is deleted from its page on Users (Off3), with the
  delete's own checks (an alias of another account, a Vault hold, secondary calendars, a data transfer still running).
- **Org units** (roadmap 4.2): create, rename and delete an org unit are curated (GamGUI #169); a slot naming the root
  (`/`, `root`, empty) is refused (`CuratedCommand.orgUnit`), never the whole organization's. Delete is destructive.
- **GamGUI's newer curated commands not here yet** (`CuratedCommandTests.notPorted`): shared drives, rename a user, delete a
  group, an admin role.
- **Deliberate differences from GamGUI's Builder**, each where a run would do what wasn't meant: a person, group or address
  field must be one address GAM acts on as given (`GamCommands.isOneAddress`: GAM reads a bare name, `oauthuser` or a list as
  someone else, a group's member is a `<UserTypeEntity>`, and GAM rewrites `uid:a@b`, `id:a@b` and `Name <a@b>` to `a@b`);
  Undelete account also takes `uid:<digits>`, GAM's own remedy when deleted accounts share an address; a choice is one GamGUI
  lists (an empty one its default, as the picker starts); Search a mailbox's "Headers + body" is listed but refused
  (`CuratedCommand.notYet`), as the other sensitive reads aren't run, by the operator's choice (no screen here reads a body);
  `target` falls back to the first address, so a new group or an undeleted account is named in the audit, not "(command)" (a
  curated read's record names it the same way);
  a delegate is checked as Users checks one (`UserChanges.checkDelegate`); suspend, the random password and a sign-out of the
  connected admin are refused by the executor, as on every screen (guard-audit: the connected-admin check); and Set title /
  department warns before GAM clears a field left empty (it sends both, as GamGUI's does).
- **Writes only through `BuilderChanges`** (`WriteRouteTests`): only `BuilderView` calls `catalogRead`; it names no other changes
  model, no executor, write or `AppServices`, and confirms nothing (its sheet does); `BuilderChanges` is named only by the
  screen, its sheet and the wiring, and nothing Siri or a model touches reaches it.

- **Another screen can open a command** (Reports' named reports): it sets `ContentView.builderCommand` to a catalog id and
  switches to the Builder, which selects it once its catalog is read, with the search and area cleared so its row is listed
  (`BuilderView.requested`, GamGUI's `/builder?cid=`); an id neither the catalog nor the curated list holds opens nothing.
- **Ask in Plain English…** (toolbar; plan F5b, Swift only): the operator types what to see or change; Apple's on-device model
  picks, each from a list made at run time (`DynamicGenerationSchema` `anyOf`, greedy, a short `asks` field first, no example

  (largest first, with a line naming Users' subcategories), Users' subcategory, then the command (curated reads first, alike

  command: Run or Preview… as always.

## Gotchas / mock-lies traps
- **The mock answers only `gam version`** of the 501. The strict mock models the exact forms this app's typed builders send
  (`formatjson` and named fields) and refuses anything else as GAM refuses what it doesn't know (`not_modelled`), never in a
  guessed shape. A generic read like bare `print users` prints GAM's flattened CSV, which the mock doesn't model: run against
  it, the Builder shows GAM's refusal. Don't widen the mock to make a screenshot run; model a shape only from GAM's source.
- **GamGUI's own caveat stands**: a grammar-valid line can still be refused live (some `print`/`show` reject what the
  grammar allows). Only the live check (B1 in docs/live-verification.md) proves a read.
- GamGUI's label code keeps the rest of a placeholder as written ("Email Address"), whatever its comment says; the fixture is
  the code's.
- **The bundled catalog isn't re-sealed at launch**: another process running as the operator could edit it. What an edit can
  do is bounded by the rules above (only argvs whose own keywords read), so it's accepted, not defended further.
- A value is trimmed as Python's `strip()` trims (`PythonText.strip`), the separator characters U+001C to U+001F too.

- **The strict mock models every curated write** (it is GamGUI's, which covered this set): a Builder change runs against it as
  the other screens' do. Its curated reads are the typed builders' forms the mock already answers.
- **Two address checks exist; the Builder needs the strict one.** `Address.looksLikeEmail` takes `uid:alice@example.com` and
  `<alice@example.com>`, which GAM rewrites to alice: with it, a suspend of the connected admin passed the refusal (review
  2026-10-28). Any field GAM reads as an account takes `GamCommands.isOneAddress`. A refusal that compares addresses compares
  what GAM will act on: ask GAM (`info user`), never the cached directory, which may not be loaded.
- The connected-admin refusal was a copy here, and Users' own Suspend had none: it is the executor's now (2026-10-28).
- `print filelist query …` isn't modelled by the mock, so the demo can't show Find a user's Drive files run.

## A step takes its values from an earlier read (roadmap 5.2, 2026-11-28; GamGUI #194's `core/sequence_binds.py`)
A curated read can now join a sequence (Add to Sequence on a read's page), and a later change's field can take
`=stepN.Column` (`GamEngine/SequenceBinds.swift`, GamGUI's syntax and words): that step runs once for each distinct row of step
N's result. **Only an earlier read with no bindings of its own feeds a step**, one source a step, never a choice field, every
other required field filled (`BuilderChanges.boundStep`). **At the preview** each read a step binds to runs once, recorded as
the Builder's reads are (`UserAccess.catalogRead`), and each row's step is built by its command's own builder; the filled-in
list is what is shown, held, guarded, run and exported. A failed read, output that isn't a table, a row missing the column or
a value the builder refuses blocks the preview; a read with no rows fills the step in for no one, said aloud. At most 500
steps once filled in; with a bound step, past 25 the count is typed. **Deviation:** Swift's sequences hold only changes, so a
read runs at the preview and not again at Run, and isn't one of the guard's targets (GamGUI runs it again as the job's step
and counts it). Held to `SequenceBindsTests` and `BuilderSequenceBindsTests`. Not run live.
