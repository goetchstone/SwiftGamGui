# Getting help

GAM GUI is maintained by one person in their spare time. Answers are best-effort, and the quickest route is usually the
one below that fits.

| You want to… | Go to |
| --- | --- |
| Build it and set it up | the [README](README.md#build-from-source) |
| Ask a question | [Discussions → Q&A](https://github.com/goetchstone/SwiftGamGui/discussions/categories/q-a) |
| Suggest a chore GAM GUI should handle | [Discussions → Ideas](https://github.com/goetchstone/SwiftGamGui/discussions/categories/ideas), or a [feature request](https://github.com/goetchstone/SwiftGamGui/issues/new/choose) if it's concrete |
| Report something broken | a [bug report](https://github.com/goetchstone/SwiftGamGui/issues/new/choose) |
| Say something worked (or didn't) on a real domain, Classroom included | the two-minute [I tried it form](https://github.com/goetchstone/SwiftGamGui/issues/new?template=live_verification.yml); it's how [live verification](docs/live-verification.md) moves |
| Report a vulnerability | privately, as [SECURITY.md](SECURITY.md) describes, never in a public issue |

**Is it GAM GUI or GAM?** Every change GAM GUI makes is one `gam` command, and the Audit screen shows it exactly. If
GAM gives the same error for that same command, the question belongs with [GAM](https://github.com/GAM-team/GAM/wiki),
or with Google: a new account can take a few minutes before Gmail and Calendar accept changes for it.

**Before you paste:** never share `oauth2service.json`, `oauth2.txt`, `client_secrets.json` or a token, and replace
your domain and real people's addresses with `example.com` ones.
